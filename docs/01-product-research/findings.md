# Findings & Decisions
<!-- English Transfer Assistant 知识库 -->

## Requirements
<!-- 用户需求清单 -->
### 目标用户
- **主要用户群体**:
  1. **职场人士**: 需要商务英语、邮件沟通、会议表达帮助
  2. **英语初学者**: 基础薄弱，经常出现语法、时态、单词错误
  3. **备考人群**: 准备四六级、雅思、托福等考试

### 使用场景
- **核心场景**:
  1. **口语练习复盘**: 练习英语口语对话后，回顾对话内容，纠正错误
  2. **聊天记录整理**: 与外教或朋友聊天后，整理和纠正对话内容
  3. **考前/面试前准备**: 准备面试、考试、演讲，需要检查英语表达是否准确
  4. **职场沟通辅助**: 工作中需要发送英文邮件/消息，想检查表达是否得体
  5. **发送前检查**: 和朋友英语对话聊天时，发送消息前先检查纠错，确保表达正确 ✨ 新增

### 产品路线图
- **v1.0 (MVP) - 批量纠错工具**
  - 粘贴对话文本
  - 4 阶段深度纠错（预处理 → 规则纠错 → LLM 优化 → 后处理）
  - 双栏对比 + 错误高亮
  - 导出学习笔记

- **v1.5 - 增强批量体验**
  - 支持导入聊天记录文件
  - 错误统计分析（易错点、进步曲线）
  - 个人学习空间（历史记录、收藏）

- **v2.0 - 实时模式**
  - 实时对话纠错
  - 快速响应模式
  - 移动端适配

### 核心功能
- **输入范围**（2026-01-19 更新）:
  - 全文本类型支持：对话、单人段落、短句、混合场景
  - 智能文本框：AI 自动识别文本类型、语气、说话人
  - 支持中英夹杂文本
  - 文本长度限制：5000 字符（MVP）

- **纠正策略**（2026-01-19 更新）:
  - 准确性优先：纠正语法错误，保留原本语气和风格
  - 自然度优先：改写成地道表达，可能调整结构
  - 用户可在输入框旁切换

- **AI 智能理解**（2026-01-19 更新）:
  - 文本类型识别：对话（格式化/自由/群聊）/ 单人文本（邮件/作文/演讲稿/短句）
  - 语气识别：正式 / 非正式 / 学术 / 商务
  - 说话人识别：显式标记 / 隐式识别 / 多人识别
  - 上下文意图理解：基于识别结果选择纠正策略

- **错误类型**:
  - 语法错误（主要类型）
    - 子分类：主谓一致、冠词使用、介词使用、句子结构
  - 时态错误（主要类型）
    - 子分类：过去时、现在完成时、将来时等
  - 单词选择错误（主要类型）
    - 子分类：近义词混淆、固定搭配、正式度
  - 中英混用错误（主要类型）
    - 子分类：词汇混用、表达习惯

- **错误分析系统**（2026-01-19 更新）:
  - 分层错误分类：4 种主要类型 + 子分类（可展开查看）
  - 结构化错误卡片：
    - 原文 → 纠正（并排对比）
    - 错误类型标签
    - 一句话解释
    - 语法规则提示（可选展开）
  - 错误统计面板：各类型错误数量、最常犯错误排行
  - 交互功能：点击卡片高亮同类错误、筛选显示

- **学习辅助功能**（2026-01-19 更新）:
  - 历史记录：自动保存最近 10 条纠错记录
  - 错误统计：总错误数、各类型占比、TOP 5 错误
  - 学习建议：基于错误模式生成建议
  - 导出功能：JSON / Markdown / PDF（v1.5）

- **核心需求**:
  1. AI 理解用户意图，正确纠正输入文本
  2. 指出原内容的具体错误（分层分类）
  3. 提供错误解释和改进建议（结构化卡片）

### 交互方式
- **界面类型**: Web 应用
- **使用模式**: 批量处理（粘贴任何英文文本）
- **输出格式**:
  - 左侧：原文（错误高亮）
  - 右侧：纠正后文本
  - 底部/右侧：结构化错误卡片（按类型分组）
- **视图切换**: 并排对照 / 仅原文 / 仅纠正后
- **布局切换**: 三栏 / 输入+对照 / 输入+分析 / 全屏对照
- **区域折叠**: 三个区域都可以独立隐藏

### 技术约束
- **部署环境**: 公网访问
- **安全要求**: 需要鉴权和限流机制
- **技术栈**:
  - 后端: Python (FastAPI)
  - 前端: Vue 3
  - 数据库: PostgreSQL（全环境使用）
  - LLM: 智谱 AI
  - 语法检查: LanguageTool

## Research Findings

### 架构选择
- **方案 1**: 双引擎纠错系统（LLM + 规则引擎混合）
- **方案 2**: LLM 优先 + 备用方案
- **方案 3**: 模块化流水线系统 ✅ 已选择

**选择方案 3 的原因**:
- 最好的输出质量
- 透明的处理流程（可调试）
- 最佳教育价值（清晰的错误分类）
- 灵活的阶段控制

### 流水线 4 阶段设计
1. **预处理阶段**: 分句、说话人识别、中文检测
2. **规则纠错阶段**: LanguageTool 处理语法/拼写/时态
3. **LLM 优化阶段**: 智谱 AI 优化表达流畅度
4. **后处理阶段**: 结果合并、格式化、错误报告

## Technical Decisions
<!-- 技术决策记录 -->
| Decision | Rationale |
|----------|-----------|
| **架构**: 模块化流水线 | 提供最佳输出质量和教育价值，便于调试和优化 |
| **后端**: Python FastAPI | 高性能异步框架，类型安全，自动生成 API 文档 |
| **前端**: Vue 3 + Composition API | 现代化响应式框架，组合式 API 更易维护 |
| **数据库**: PostgreSQL | 全环境统一使用，支持复杂查询和 JSON 类型 |
| **LLM**: 智谱 AI | 国内访问稳定，中文理解能力强，成本可控 |
| **语法检查**: LanguageTool | 开源、准确、支持多种错误类型 |
| **认证**: JWT Token | 无状态认证，适合前后端分离，支持刷新令牌 |
| **限流**: Redis + 分层策略 | 高性能计数器，支持多层级限流（匿名/免费/付费） |
| **输出格式**: 双栏对比 | 直观对比原文和纠正内容，便于学习 |
| **产品策略**: 批量优先（MVP） | 5 个场景中 4 个是批量，技术可行性和教育价值更高 |
| **v2.0 实时模式**: 后期迭代 | 实时翻译需要快速响应和更高成本，适合成熟期 |

### 产品决策
**为什么选择批量处理作为 MVP？**
1. **需求覆盖度**: 5 个场景中 4 个是批量（口语复盘、聊天整理、考前准备、职场辅助）
2. **目标用户匹配度**:
   - 初学者：练习后系统复盘，详细学习错误
   - 备考人群：需要完整纠错分析和解释
   - 职场人士：准备邮件/演讲稿时批量检查
3. **技术可行性**:
   - 批量模式可以深度分析（4 阶段流水线，输出质量最高）
   - 实时模式需要快速响应（< 1秒），可能牺牲准确性
   - 成本可控：批量处理可以优化 API 调用
4. **产品价值**:
   - 批量纠错有教育价值：详细展示错误类型、位置、解释
   - 用户可以反复学习，而不只是看到翻译结果

### 安全机制
1. **JWT 认证**
   - access_token（15 分钟）
   - refresh_token（7 天）
   - 邮箱注册/登录
   - 可选 OAuth（Google/GitHub）

2. **速率限制**
   - 匿名用户: 5 次/小时
   - 免费用户: 50 次/天
   - 付费用户: 500 次/天
   - IP 级别防滥用

3. **内容安全**
   - 输入长度限制: 5000 字符
   - 敏感内容过滤
   - CORS 配置

4. **API 安全**
   - HTTPS 强制
   - API Key 管理
   - SQL 注入防护（ORM）
   - 请求体大小限制

### 数据库设计
**4 张核心表**:
- `users`: 用户信息（邮箱、密码、套餐）
- `conversations`: 对话记录（原文、纠正文本、错误统计）
- `error_details`: 错误详情（每句话的错误位置和解释）
- `request_logs`: 请求日志（用于限流和分析）

**索引优化**:
- user_id 外键索引
- conversation_id 外键索引
- user_id + created_at 复合索引（查询优化）
